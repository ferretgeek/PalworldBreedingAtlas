## 来源策略

1. Pocketpair 官方公告与本机 Steam manifest：版本、build、正式数量和规则变化的硬锚点。
2. 固定 commit 与 SHA-256 的 PalCalc CUE4Parse 导出：当前名称、内部 ID、数值、工作适性和配种矩阵的可重复结构化输入。
3. 本机同版本 PAK、本地化和图标资源：资源核对与未来直接字段导出。
4. 版本化 ModdingKit：解释 schema，不替代数据。
5. PalDB.cn、Palworld.gg、PalworldBreed 等：独立差异检查和争议配方复核，不直接覆盖主输入。

禁止把无版本标记、早于 1.0、无法固定快照或与官方 287 条不符的数据并入正式数据。社区帖子只能发现异常，不能代替可复算证据。

## 已审查来源结论

| 来源 | 作用 | 结论 |
|---|---|---|
| Pocketpair 1.0 公告 | 287 条及规则变化 | 最高级版本锚点，不提供完整矩阵 |
| `tylercamp/palcalc` 固定 commit | 299 源条目和 44,851 源配方行 | 当前结构化主输入，可固定 commit 与哈希 |
| PalDB.cn | 1.0 中文 API | 核心交叉源 |
| Palworld.gg | 配种力 | 普通公式交叉复算 |
| PalworldBreed | 前向查询 | 配方交叉源 |
| Game8、Host Havoc、GenshinLab | 更新监测 | 实现不可完整审计，不作主源 |
| Supercraft、Multicalify | 覆盖不足或新鲜度可疑 | 不用于 1.0 全量校验 |

## 正式图鉴过滤

结构化输入原始 `Pals` 为 299 条：

- 排除 `PalDexNo >= 10000` 的 11 个无正式图鉴编号单位；
- 排除不单列图鉴的 `PlantSlime_Flower`；
- `#204 WorldTreeDragon / Astralym` 只作为隐藏剧情/Boss 记录，不进入默认 287；
- Terraria 联动、重复和未完成单位不得进入普通图鉴与配种池；
- 正式输出必须严格断言为 287 条。

相对旧 284 条基线，移除旧 `204 WorldTreeDragon`，新增 `143 妮瞅莎`、`147 梅莉姆`、`154 金驰兽`、`165 詹兔曼`。

## 配种与工作适性门禁

- 先匹配特殊组合和亲本性别要求；
- 普通 rank 结果只能来自有效普通池；
- `IgnoreCombi=true` 不得进入普通结果；
- 平均 rank 相同时使用 `CombiDuplicatePriority`；
- 亲本顺序去重，但性别限制不能丢失；
- 所有父母和子代必须引用现有稳定字符串 key。

争议哨兵：

```text
棉悠悠 3050 + 海月灵 2590
平均值 2820 -> 棉花糖 2820
不得错误落到姬小兔 2860
```

该结论已由固定 PalCalc 数据、PalDB.cn 1.0 API、PalworldBreed 前向结果和 Palworld.gg 配种力交叉核对。

基础工作适性最大值和系统强化上限必须分别记录：

```text
maxBaseWorkSuitability = 8
workSuitabilityCap = 10
```

## 关键游戏资源

- `DT_PalMonsterParameter`：图鉴号、内部 ID、稀有度、基础数值、工作适性、配种力、优先级和角色标志；
- `DT_PalCombiUnique`：特殊配种和亲本性别限制；
- 官方本地化：中英文名与描述；
- 图标表和 `Pal/Texture/PalIcon/Normal`。

## 生成与验证

在项目根目录运行：

```powershell
python .\tools\update_game_data.py `
  --db 'C:\path\to\db.json' `
  --breeding 'C:\path\to\breeding.json' `
  --steam-manifest 'C:\path\to\appmanifest_1623730.acf'

.\scripts\verify.ps1
```

生成器必须：

- 核对固定输入哈希；进入新版本更新流程前不得绕过；
- 不硬编码用户名、Steam 盘符或临时路径；
- 原子替换单文件，多文件失败时在进程内尝试恢复；
- 同步生成 provenance 和内部 ID 映射；
- 输出读取、排除、正式条目、配方和失败数。

进程内恢复不等于可抵御断电的文件系统事务。中断后必须重新生成并跑完整门禁。

## provenance 最低要求

- schema 与生成器版本；
- App ID、build、depot manifest；
- 官方公告 URL、时间和正式数量；
- 固定输入 commit 与输入 SHA-256；
- UTC 生成时间；
- 过滤清单与原因；
- 各阶段数量、输出哈希和校验结果；
- 元素来源状态、版本/build、覆盖数、URL 和哈希；
- 缺失图标与占位清单。

不得写入本机绝对路径、用户名、Steam 库盘符、账号或私人存档信息。

## 新版本更新检查表

1. 读取实际 Steam manifest，不按发布日期猜 build。
2. 阅读官方 changelog，确认图鉴、配种和存档变化。
3. 提取同 build 的关键 PAK 资产与本地化。
4. 更新固定结构化输入 commit 和哈希。
5. 属性优先使用直接 PAK 导出；第三方快照必须固定 URL、页面哈希、版本/build 和 287 内部 ID 完整集合。
6. 审核隐藏 Boss、联动、重复和未完成单位过滤。
7. 用生成器重建，禁止手改生成文件。
8. 运行数据契约、求解器、真实存档和 UI 回归。
9. 更新本文与 `版本记录.md`。
10. 仅 UI、缓存或存档逻辑变化时明确写“游戏数据基线未变”，不伪造新数据版本。

出现两个以上同 build、无 MOD、信息完整的可复现反例时，应暂停交付当前矩阵并优先重新导出数据。
